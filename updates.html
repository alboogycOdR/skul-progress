16 May 2026H.4 + H.6Queued

Auth direction change — Microsoft in, Facebook out, Turnstile added

Re-framed the OAuth strategy. Microsoft replaces Facebook as the second sign-in provider, and Cloudflare Turnstile is added as spam protection on the email registration form. The visual design of /register stays as-is — only the functional surface changes: a Google button, a Microsoft button, and a Turnstile challenge before "Create free account". This is a planning + spec change today; the build is queued (status PEN) and starts as soon as the credentials are issued.

Implementation notes

  • H.4 reframed from "Add Facebook sign-in" → "Add Microsoft sign-in (personal + Microsoft 365 / Entra ID via the `common` tenant)". Microsoft uses standard OIDC — same shape as Google, no special `/debug_token` round-trip like Facebook required.
  • H.6 added (new) — Cloudflare Turnstile on the registration form. Privacy-friendly alternative to reCAPTCHA; no Google tracking; free at our volume.
  • Why Microsoft over Facebook: no business verification, no App Review (which would have cost 1–2 weeks of calendar time at Meta), no mandatory /data-deletion endpoint, no quarterly Graph-API breaking changes. Reaches a similar audience with materially less operational overhead.
  • Spec docs updated: 00_overview.md, CLIENT_BRIEFING.md, 03_email_password_spec.md cross-refs. 02_facebook_oauth_spec.md retired (file deleted). New: 02_microsoft_oauth_spec.md and 04_spam_protection_spec.md.
  • Open question Q3 in the frontend plan is now resolved (Google + Microsoft + Email; WhatsApp deferred indefinitely; Facebook dropped).
  • Build will start once the user issues: Microsoft Entra ID app (Client ID + Secret) and Cloudflare Turnstile site (Site Key + Secret Key). Both setups are self-service and take roughly 15–20 minutes combined.
16 May 2026F.4QA review

Contact page (skeleton) — fixes broken /contact link

The landing page's nav and hamburger menu have linked to /contact for a while, but the route was never defined — meaning anyone tapping "Contact Us" got bounced to the login page (preact-router falls back to /login for unknown paths). Shipped a static contact page that resolves the broken link with two email cards (support and general enquiries) plus a clear "contact form coming soon" note. Functionally complete for the skeleton scope; the full form is deferred until Q8 (where do submissions go?) is answered.

Implementation notes

  • New page: frontend/src/pages/readmore/ContactPage.jsx — matches the header / kicker / h1 pattern used by /about, /how-it-works, /learning.
  • Two channels surfaced: support@skul.co.zm (account, billing, technical) and info@skul.co.zm (general). Both use mailto: links so the user's email client opens.
  • No form, no backend touch points, no Q8 commitment yet — purely a static info page.
  • Sets a parent / guardian privacy-concern hint to help with safeguarding-flagged enquiries.
  • When you're ready, the next call is Q8 in the frontend plan: where should form submissions go? Once decided, F.4 progresses to the full form variant.
